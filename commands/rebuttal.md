# /rebuttal — Rebuttal / Response to Reviewers

主要参考 `knowledge/templates/rebuttal.md`。

## 流程

1. **接收 reviews**：让 Hollis 粘贴 reviewer 评论（每个 reviewer 独立段落）
2. **分类问题**：
   - 真错（必须承认 + 修）
   - 可补实验（rebuttal 期补一个有杀伤力的）
   - 误解（澄清 + 修改原文）
   - 主观分歧（礼貌坚持 + 给数据）
3. **逐条草稿**：用 `knowledge/templates/rebuttal.md` 中对应类型的模板
4. **字数控制**：
   - NeurIPS: 6 页 PDF
   - ICML: 5000 字符 / 全局
   - ICLR: 不严格但建议 < 1500 词 / reviewer
   - CVPR: 1 页 PDF
   - ACL ARR: 800 字 / reviewer
5. **AC tagging**（最后 1 段）：感谢 + 强调 reviewer 之间的共识 / 帮 AC 整合分歧

## 必检清单

- [ ] 每条 review 都有回应（不能漏）
- [ ] 至少补 1 个新实验 / 新数字
- [ ] "Summary of Changes" 段落明确列出 camera-ready 改动
- [ ] 措辞专业（公开评审如 ICLR 尤其重要）
- [ ] 不直接说 "reviewer is wrong"
- [ ] 字数 / 页数符合会议要求
- [ ] 表格 / 图清晰

## 推荐工作流

1. 拿到 review 当天**只通读，不写**
2. 第二天列 TODO + 实验计划
3. 中间几天集中补实验
4. 截止前 2 天写完初稿
5. 截止前 1 天 review + 字数检查
6. 截止当天上午提交（不要拖最后一刻）
